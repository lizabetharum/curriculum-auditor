This tool reads a lesson, finds which XQ skills it teaches, and scores student work. Claude, an AI model, makes each decision. Code checks each one before it counts.

Who it’s for. The tool is for teachers and curriculum teams who want to check a lesson against the XQ Competencies and get a first pass on student work. The notebook is for people learning to build AI agents: it teaches how the tool was built, with exercises. Students never use it. Their work is what gets scored.

Use It

The Teacher App

Upload a lesson in Word or PDF. See which XQ skills each part teaches, with quotes, and which answers in the answer key look wrong. Then score student work.

  • Word files are split at their headings, PDFs by page
  • Wrong answers are found by code, wrong setups by Claude
  • Each student response is scored three times, and the most common result wins. When the runs disagree, the teacher is told to look
  • Nothing is saved on the site. Reports download to your computer
  • No student names allowed. Password protected
Password available on request. Every result is a first draft for a teacher to check.

Decisions I Made

  • Code checks every claim. I required every score to quote the student's own words, and every math answer to be worked out again by code, never by the AI.
  • I scored first, blind. I scored all 32 pairs before Claude scored anything, so Claude's answers could not shape mine.
  • No work gets no score. Work with nothing to judge is not Level 1. I settled that rule with a colleague and held Claude to it.
  • I tested the checks with planted mistakes. I had the test lesson written with three hidden errors, chosen to show what code can catch and what only a reader can.
  • I published the weak spots. I set no pass mark in advance and reported every number, including the ones that do not flatter the tool.

What It Found

Errors in the answer key. The test lesson had three planted mistakes. Code found two: a calculator set to radians (6.15 m instead of 13.22 m) and a missing 1.5 m. Claude found the third: cosine used where sine was needed. Claude also found a mistake nobody planted.

Claude's scores compared with mine. I scored 16 student responses on 2 skills each before seeing Claude's scores. When we both gave a level, we were never more than one level apart. Exact matches ranged from 86% to 91% across three runs. The main disagreement: on 5 scores where the student did only a little work, such as a bare "0.31" or a one-line answer, Claude said the work showed too little to score, and I gave it Level 1. Where there was no work at all, we agreed on 0.

Claude does not always agree with itself. I had Claude score the same work three times. 25 of 30 scores came out the same every time. The other 5 changed: 2 moved by one level, and 3 moved between Level 1 and "too little to score."

Why it happens. Claude does not compute a score the way a calculator does. Each time, it reads the work, reasons through it, and writes an answer, and that process has some randomness built in. Clear-cut work lands in the same place every time. Work that sits between two levels can land on either side.

Why it matters. One run's score is not the final word. For real grading, score each piece of work more than once, keep the level that comes up most often, and send any work where the runs disagree to a teacher. Those are the borderline cases a person should look at anyway.

The teacher app scores every response three times. On my 32 scores, that did not make Claude agree with me more: the majority matched me 21 times, about the same as a single run. What it did was flag the 7 scores where the runs disagreed, which are the calls a teacher should check. It could not fix the biggest disagreement, where all three runs agreed with each other and not with me, on work with nothing to judge. Voting catches uncertainty. Only settling the rule with the teacher fixes a disagreement about the rule.

Limitations

  1. One rater. Only one teacher scored the work, so there is no measure of how often two teachers agree. Without that baseline, nobody can say whether Claude's agreement is good or bad.
  2. The student work is synthetic, and Claude wrote it. Real students write differently, and Claude may find its own writing easier to score.
  3. The sample is small. 16 responses and 32 scores. Changing one or two scores moves the results a lot.
  4. The skill matching was never checked by a person. Only the scores were compared with a teacher.
  5. The rule for "no work" was not set in advance. Most disagreements sit there, and one label changed twice before settling. The full history is disclosed.

Five more limitations are listed in the project README.
